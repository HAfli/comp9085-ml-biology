# COMP9085 — Machine Learning and Foundation Models for Biology, Healthcare and Nutrition

An interactive course website for the MSc module COMP9085 at Munster
Technological University, Department of Computer Science.

> **The argument of the module.** Foundation models do not replace
> machine-learning fundamentals. They build on them.

It is a static site: no backend, no build step, no framework. Open `index.html`
and it works. It deploys to GitHub Pages by pushing it.

---

## What makes this different from a slide deck on the web

**The figures compute.** Sixteen interactive components, and they are not
animations of pre-recorded results. When you move the depth slider on the
decision tree builder, a CART tree is genuinely fitted to the real UCI Breast
Cancer Wisconsin data in your browser and the tree you see is the tree that was
fitted. `js/ml.js` contains working implementations of decision trees, random
forests, k-NN, multinomial naive Bayes, logistic regression, PCA by Jacobi
eigendecomposition, k-means, DBSCAN, agglomerative clustering, silhouette
scoring and the adjusted Rand index, all seeded so two students see the same
result.

**Provenance is visible.** Every figure carries a banner saying whether its data
is real or simulated, and those banners are generated from flags inside the data
files rather than written by hand. Two datasets on this site are simulated; both
say so on every screen they appear on, and both ship the script that generated
them. Nothing invented is presented as measured.

**Every chart has a text alternative.** Under each figure is a disclosure
containing the same information as tables and prose. It is not a caption; it is
the full content, so the site is usable by screen-reader users, by anyone who
would rather read numbers than look at a chart, and in print.

**The slides are the university's own slides, updated.** Twelve decks in
PowerPoint and PDF, 26 to 49 slides each, built on the **actual MTU master**
taken from the 2025/26 COMP9085 deck: the same crest, background artwork,
"Succeeding Together" band, layouts, embedded fonts and colour scheme, inherited
from the original file rather than reconstructed. The content is generated by
`slides/build_slides.py` from `js/data/course.js`, so a change to a week
changes both the website and the deck and the two cannot drift apart. Every
deck carries full-slide panels pointing at the matching interactive figure on
the site; `docs/SLIDE_WEBSITE_MAP.md` lists them all.

## Running it locally

Because the site loads its data as JavaScript rather than fetching JSON, it works
straight off the filesystem:

```bash
open index.html          # macOS
xdg-open index.html      # Linux
```

A local server is still slightly better, and is what the tests expect:

```bash
python3 -m http.server 8899
# then visit http://localhost:8899
```

Nothing needs to be installed to view the site. Python is needed only to
regenerate the data files or to run the tests.

## Figures are fitted models, not pictures of models

Every interactive figure draws an object that was actually fitted, in the
browser, on the data its banner names. Move a control and the model is refitted;
the diagram and the numbers cannot disagree, because they come from the same
object.

`js/visualisations/_model.js` is the shared layer that makes this reusable: it
draws fitted trees, traces one case through one, and renders the node inspector
and the decision path. Week 2 uses it three times — the tree builder, the
entropy visualiser and the deployment demonstration — and
`docs/MODEL_VISUALISATION.md` sets out the contract for the models in the later
weeks.

Week 2 also carries a **deployment demonstration**: an application-shaped
interface where a case is entered, evaluated by the same tree, and returned with
its decision path, the statistics of the leaf it reached, the model's own
details, and eight questions about whether the result should be trusted.
Out-of-range inputs are flagged against the real dataset range; no clinical
reference range is invented, and the page states on every screen that it is an
educational demonstration and not a clinical diagnostic system.

## Links you must set

Every external link and every video ID lives in **`js/config.js`** and nowhere
else. Each entry carries a `status` field. Anything not marked `'confirmed'`
renders on the site as a visible, clearly-marked placeholder rather than a
broken or invented link.

| Entry | Status as shipped | What to do |
|---|---|---|
| `links.academicWebsite` | `confirmed` | Nothing |
| `links.moduleDescriptor` | `confirmed` | Nothing |
| `links.aiForIrish` | **`placeholder`** | Set `url` to the real address and change `status` to `'confirmed'` |
| `links.canvasCourse` | **`placeholder`** | Set it once the Canvas course exists, or leave it out |
| `youtube.week1BiologyMeetsCS` | `confirmed` | Nothing |
| `youtube.week1AlphaFold` | `confirmed` | Nothing |

The AI for Irish URL was deliberately **not** guessed. It could not be
established from the module materials, the repository or the project, so it is
a placeholder with a note explaining exactly that. Filling it in is a
two-second edit; an invented URL would have been a permanent quiet error.

To add a video of your own, add an entry to `youtube` with `id: null` and
`status: 'awaiting-upload'`, then add its key to the `videos` array of the
relevant week in `js/data/course.js`. The page renders a placeholder card with
the upload instructions on it until you set the ID.
`docs/VIDEO_SOURCES.md` has the full procedure, including the YouTube metadata
to use and why the two existing MP4s must **not** be re-uploaded.

## Lecture slides

Twelve decks, in both PowerPoint and PDF:

```
slides/weekNN/COMP9085_WeekNN.pptx
slides/weekNN/COMP9085_WeekNN.pdf
```

They are linked at the top of every week page, on `resources.html#lectures` and
on `canvas.html`.

They are built on `slides/template/MTU_COMP9085.pptx`, which is the 2025/26
COMP9085 deck with its slides removed and its master, layouts, theme, MTU
artwork and embedded fonts left intact. Nothing about the MTU identity is
redrawn in code.

### Rebuilding them

```bash
pip install python-pptx pillow
sudo apt-get install libreoffice          # only needed for the PDF export
python3 slides/build_slides.py            # all twelve
python3 slides/build_slides.py 7          # just week 7
python3 slides/build_slides.py 2 3 4      # a few
python3 slides/build_slides.py --no-pdf   # PowerPoint only, no LibreOffice needed
python3 slides/audit_slides.py            # structural check on all twelve decks
python3 docs/build_slide_map.py           # refresh the slide-to-website map
```

For faithful PDF output install IBM Plex Sans Condensed, the master's font.
Without it LibreOffice substitutes and the PDFs drift from the PowerPoint; the
`.pptx` files are unaffected either way, because the fonts are embedded in
them.

`build_slides.py` reads the week's content out of `js/data/course.js` and
`js/data/labs.js` (via `node -e`), composes the deck from the layouts in
`slides/template.py`, and pulls the equations, algorithm boxes and worked
numbers for that week from `slides/technical.py`. Week 1 is the exception: it is
hand-authored in `slides/week01.py`, because it is a rebuild of the original
52-slide deck. `docs/WEEK1_SLIDE_MAPPING.md` records what happened to each of
those 52 slides and to each image in them.

If LibreOffice is not installed, the PPTX files are still written and only the
PDF step is skipped, with a warning telling you which decks are missing a PDF.

### QR codes for the lecture theatre

The slides print the page path in monospace, which is enough to type. If you
want QR codes instead, once you know your deployed URL:

```bash
pip install "qrcode[pil]"
python3 docs/build_slide_map.py --qr --base https://USERNAME.github.io/REPO/
```

This writes one PNG per week into `slides/qr/`. They are not committed, because
the base URL is not known until you deploy.

## Using it in Canvas

`docs/CANVAS_GUIDE.md` covers three options in full. The short version: publish
the site, then add external-URL module items in Canvas pointing at
`start-here.html` and each `weeks/weekNN.html`, and keep assignments,
submissions and grades in Canvas. `canvas.html` exists for the case where you
want the week table embedded inside a Canvas page instead; it has no site header
or footer and every link inside it targets `_top`.

Nothing about this requires an LTI integration, a login, a database or cookies.

## Deploying to GitHub Pages

### First deployment

```bash
cd comp9085-ml-biology

git init
git add .
git commit -m "COMP9085 course website"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPO.git
git push -u origin main
```

Then in the repository on github.com:

1. **Settings** → **Pages** (left sidebar)
2. Under **Build and deployment**, set **Source** to **Deploy from a branch**
3. Set **Branch** to `main` and the folder to **`/ (root)`**
4. Click **Save**

The site appears at `https://YOUR-USERNAME.github.io/YOUR-REPO/` within a couple
of minutes. GitHub shows the URL at the top of the same Pages settings screen
once the first build finishes.

### Subsequent updates

```bash
git add .
git commit -m "Update Week 7 worked example"
git push
```

Pages redeploys automatically, usually within a minute.

### Notes

- **`.nojekyll` is required and is already in the repository.** Without it,
  GitHub runs Jekyll over the site, which ignores directories beginning with an
  underscore. `js/visualisations/_chart.js` would silently vanish and every
  figure would fail.
- **Every path is relative,** so the site works at a project URL
  (`username.github.io/repo/`), at a custom domain, in a subdirectory, or off
  the local filesystem, with no configuration.
- **No CDN dependency.** D3 is vendored in `js/vendor/`, so the site works
  offline and does not break if a CDN is blocked on a campus network.
- **For a custom domain,** add a `CNAME` file containing the domain and set it
  in Settings → Pages.

## Regenerating the data

Only needed if you want to change what the figures compute on.

```bash
pip install numpy pandas scikit-learn

python3 data/scripts/01_build_wdbc.py         # real WDBC
python3 data/scripts/02_build_benchmarks.py   # real measured results
python3 data/scripts/03_build_sequences.py    # simulated protein set
python3 data/scripts/05_build_recalls.py      # illustrative corpus
```

### Substituting real ESM-2 embeddings

Script 03 produces a documented *simulation* of a protein language model
embedding, so that the site works on a machine with no GPU and no internet. If
you have both, run:

```bash
pip install torch transformers
python3 data/scripts/04_real_esm2_embeddings.py
```

This runs the same sequences through `facebook/esm2_t6_8M_UR50D` (about 100 MB,
a couple of minutes on a laptop CPU), replaces the embedding block, and sets
`simulatedEmbedding: false`. **The site reads that flag**, so every banner,
caption and text alternative updates itself to say the embeddings are real. The
sequences remain simulated and the site keeps saying so.

Use `--model facebook/esm2_t12_35M_UR50D` or `--model facebook/esm2_t33_650M_UR50D`
for a larger checkpoint.

## Testing

```bash
pip install playwright && playwright install chromium
python3 -m http.server 8899 &

python3 data/scripts/test_site.py          # 20 pages, links, accessibility
python3 data/scripts/test_interactions.py  # drives every control on every figure
```

`test_site.py` checks every page renders, throws no JavaScript errors, mounts
its header and footer, has exactly one `h1`, resolves every internal link, gives
every figure a populated text alternative and a reset control, labels every form
control, and does not overflow horizontally at 390 px.

`test_interactions.py` sweeps every slider to both extremes and the midpoint,
selects every option of every dropdown, toggles every checkbox, clicks every
segmented control and in-figure button, checks the reset control restores a
working state, and fails if a figure's output is unchanged after all of that —
which catches a figure that draws correctly but ignores its own controls.

Both are worth running after any content change. They caught seven real bugs
during development.

## Editing content

**The rule: content lives in `js/data/`, never in HTML.** The HTML files are
generated shells. Editing them by hand works until someone runs the build
script, at which point the edit is gone.

| To change | Edit | Then |
|---|---|---|
| The Week 2 model, its numbers or its figures | `data/scripts/06_build_week02.py` | Re-run it, then rebuild the Week 2 deck |
| The Week 2 lab | `data/scripts/07_build_week02_lab.py` | Re-run it; the solutions are re-executed |
| A week's objectives, concepts, worked example, quiz | `js/data/course.js` | Reload |
| A lab | `js/data/labs.js` | Reload |
| A dataset entry | `js/data/datasets.js` | Reload |
| A foundation-model entry | `js/data/models.js` | Reload |
| A citation | `js/data/references.js` | Reload |
| Colours, spacing, type | `css/main.css` (tokens at the top) | Reload |
| A figure's behaviour | `js/visualisations/<name>.js` | Reload |
| A figure's controls | `VIZ_SPECS` in `js/week-page.js` | Reload |
| The navigation | `NAV_ITEMS` in `js/navigation.js` | Reload |
| A video ID, or an external link | `js/config.js` | Reload |
| Slide content | `js/data/course.js`, then `slides/technical.py` for the equations | Re-run `slides/build_slides.py` |
| A page shell | `build_pages.py` / `build_top_pages.py` | Re-run it |

`docs/MAINTENANCE.md` has worked examples of each, including how to add a
thirteenth week and how to add a new interactive figure from scratch.

## Accessibility

- Semantic HTML with landmark elements and a skip link
- Full keyboard navigation, with a visible focus ring on every control
- Every figure has a complete text alternative, not a summary
- Colour is never the only channel: every categorical series carries a distinct
  shape as well as a colour, and the palette is chosen to remain distinguishable
  in the common forms of colour vision deficiency
- Every form control has an associated `<label>`; segmented groups use
  `role="group"` with `aria-labelledby` and `aria-pressed`
- Live regions announce results in the quizzes and check-ins
- Respects `prefers-reduced-motion` and `prefers-contrast: more`
- Print stylesheet expands every text alternative, so a printed page carries the
  data that the interactive figure would have shown
- Tested at 390 px, 768 px and 1280 px

## Privacy

The site stores three things in the browser's `localStorage` under keys
beginning `comp9085.`: which weeks have been opened, weekly check-in answers,
and self-check results.

There is no server, no account, no cookie, no analytics and no third-party
request of any kind. D3 is served from this same site. Nothing a student types
is transmitted anywhere, and the lecturer cannot see it. Students can export or
clear everything from the resources page. All storage access is wrapped in
`try`/`catch`, so the site works normally in private browsing and where site
data is blocked.
